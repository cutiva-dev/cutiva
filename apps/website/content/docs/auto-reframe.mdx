title: Auto-reframe
description: Turn landscape footage into vertical video that follows whoever is talking.
---

**Status: beta, needs testing.** E2E tests check, in Chrome and Firefox, that dragging the window changes both preview and export, and that the editor's reframe controls work on a synthetic two-speaker clip (with a stand-in face detector): lanes, clicking a face, layouts, people, camera style, undo, save and the analysis cache. A manual test (it needs the network) checks that MediaPipe loads and analyses a clip. Another E2E test draws a single, a wide and a split segment and checks that the exported MP4 shows what the preview shows (colours and face edges within 2 output pixels, at three instants). On one real 48 s clip (a podcast, three people side by side, 1080p) the detector finds all three in 223 of 242 analysed frames, and the camera moves between the three speakers in step with whose lips move (checked against the lip measure, not yet against a labelled transcript). Analysis of that clip takes about 58 s in Chrome on an M-series Mac, more than the clip's length.

Auto-reframe crops a landscape clip for a vertical (or square) project. It watches the clip, finds the people, works out who is talking from mouth movement and speech, and splits the clip into **segments**: who is framed, and how (one person, a split for two, or wide). The camera cuts to each new speaker and follows gently while they move. You fix what it gets wrong with a click: pick a face, a layout or a person's flags, and that segment stays as you set it. A split shows one person in each half of the frame; wide shows the whole picture over a blurred copy of it.

## Web

Set the project's format, then reframe a clip. Face detection is pluggable; `@cutiva/web/mediapipe` provides a detector on MediaPipe Face Landmarker (Apache-2.0). Install it yourself, it is an optional peer dependency:

```bash
npm install @mediapipe/tasks-vision@1.1.1
```

```ts
import { createEditor } from "@cutiva/core";
import { createWebEngine } from "@cutiva/web";
import { createMediaPipeFaceDetector } from "@cutiva/web/mediapipe";

const editor = createEditor();
const engine = createWebEngine(editor);
const { clipId } = await engine.importFile(file);

editor.dispatch({ type: "project.setSize", width: 1080, height: 1920 }); // 9:16
const detector = await createMediaPipeFaceDetector();
const result = await engine.reframe(clipId!, {
  detector,
  onProgress: (ratio, stage) => console.log(`${stage} ${Math.round(ratio * 100)}%`), // stage: "video", then "audio"
});

result.track.people;   // [{ id: "p1", label: "Speaker A", kind: "face", priority: false, neverFocus: false }, ...]
result.track.segments; // [{ id: "s1", startUs: 0, endUs: 4_200_000, speakers: ["p1"], resolved: "single", locked: false, ... }, ...]
editor.undo();         // the whole reframe is one undo step
```

`engine.reframe` runs the [reframe planner](#the-reframe-planner) and stores its Reframe Track and keys in the clip's `core/reframe` effect, so undo, Save project and export need nothing else. Analysis decodes 5 frames per second, which is the slow part (about a minute for a three-minute clip). The older `engine.autoReframe(clipId, { detector, zoom })` still works: it writes keys only, with the planner under [How it decides](#how-it-decides).

### Editing the framing

Every change is a `ReframeEdit` applied with `engine.editReframe(clipId, edit)`: the engine edits the track, re-plans from the cached analysis (about 20 ms for three minutes) and applies the result as one undo step. Pass an array to apply several edits as one step.

```ts
const seg = result.track.segments[2]!;
await engine.editReframe(clipId, { type: "segment", segmentId: seg.id, focus: ["p2"], layout: "single" }); // frame p2 here
await engine.editReframe(clipId, { type: "segment", segmentId: seg.id, layout: "wide" });                 // or show everything
await engine.editReframe(clipId, { type: "segment", segmentId: seg.id, window: { x: 960, y: 540, h: 1080 } }); // a dragged window
await engine.editReframe(clipId, { type: "reset", segmentId: seg.id });                                   // back to automatic
await engine.editReframe(clipId, { type: "person", personId: "p1", label: "Host", neverFocus: true });
await engine.editReframe(clipId, { type: "merge", personId: "p3", intoId: "p1" });                         // the same person
await engine.editReframe(clipId, { type: "settings", style: 0, zoomPct: 120 });                           // calm, 1.2x
```

Segment edits lock the segment: re-planning (after a person edit, a style change or a new analysis) never changes it. `engine.reframePlan(clipId, edits?)` returns the plan without changing the project: its `sightings` say where each person's face was seen (for clickable faces and avatars), and with `edits` it previews a change or builds plans for several clips to apply in one `editor.batch`.

Observations stay out of the project ([ADR 0006](https://github.com/cutiva-dev/cutiva/blob/main/docs/adr/0006-reframe-track-in-cpf.md)): the engine keeps each analysis in memory and in IndexedDB, keyed by the file's size and the SHA-256 of its first 64 KiB, so it survives a reload. Without it (another device, cleared storage) `editReframe` throws `ANALYSIS_NEEDED`: analyse again with `engine.reframe(clipId, { detector, reanalyze: true })`. The track keeps names, flags and locked segments either way, and the clip still previews and exports.

The MediaPipe detector downloads its WASM files from jsDelivr and its model (about 3.7 MB) from Google the first time. The model is checked against a pinned SHA-256 (`MEDIAPIPE_MODEL_SHA256`) and kept in Cache Storage, so later loads don't download it again; a cached copy with the wrong hash is thrown away. Pass `wasmBaseUrl` and `modelAssetPath` to host the files yourself, `modelSha256` if you host a different model, and `onProgress` to show the download. A failed download, a hash mismatch or a runtime that doesn't start throws `MODEL_LOAD_FAILED`. Video frames never leave the device.

MediaPipe shrinks every image to 192 px before it looks for faces, so in a wide shot (three people at a table, faces a tenth of the frame's height) it finds none in the whole frame. The detector therefore also looks in overlapping square tiles, two thirds of the frame's shorter side each (4 × 2 on a 16:9 frame), and keeps one box per face: boxes that overlap (IoU 0.3, or half of the smaller inside the larger) are the same face, and the largest wins. Pass `tiles: false` to look at the whole frame only, which is about nine times faster and fine for close-ups. Mouth openness is the gap between the inner lips (landmarks 13 and 14) over the face's height: 0 closed, about 0.3 wide open. The `jawOpen` blendshape stays near zero on small faces.

`analyzeAsset` throws `NO_VIDEO_TRACK` for an asset without video and `ANALYSIS_CANCELLED` when its `signal` aborts.

### What the analysis records

`result.analysis` holds numbers only, never images or audio. Sizes come from the video track's display size, so rotation metadata and non-square pixels are already applied.

- **Faces** per analysed frame, in source pixels: box, mouth openness (`null` when the detector can't see the mouth) and, if the detector gives one, a confidence. MediaPipe gives no confidence.
- **Speech level** per frame: loudness within 100 ms on each side, relative to the clip's 90th percentile, from 0 to 1.
- **Stereo pan** per frame, from -1 (left) to 1 (right): `stereoPan` in the core computes `(R − L) / (R + L)` of the energy within 100 ms on each side. Absent when the file is mono or its two channels carry the same signal (their difference holds under 0.1% of the energy); silence gives 0.
- **Camera cuts**, from colour histograms.
- **Active area** (`activeArea`), the picture inside burned-in black bars. Each pixel keeps its brightest value across the sampled frames, on a copy 320 pixels wide, and `detectActiveArea` in the core reads it: a row or column is a bar when 95% of its pixels are at luma 32 or below, counted only from the edges inwards. Bars under 2% of a side are ignored, and if less than half of either side would remain the clip is treated as a dark scene (no active area). The result is rounded inwards to whole source pixels. Fixtures `signals-*.json` pin both functions for TypeScript and Dart.

`autoReframe` doesn't use pan, confidence or the active area; `planReframe` does.

## React

`<Timeline>` marks each framing change on the clip; click a mark to seek there. Under a video track with a reframed clip it adds two lanes: **Speakers** (who talks, coloured by person) and **Camera** (what each segment frames; locked segments carry a mark). Clicking a segment calls `onSelectSegment(clipId, segmentId)` and moves the playhead to its middle; `selectedSegment` highlights one; `reframeLanes={false}` hides them.

`<ReframeBox>` draws the crop window over the uncropped source. Without a Reframe Track, dragging it moves the key at the playhead. With one, pass `onWindow` and turn the drop into a segment edit that locks it; pass `faces` (for example from `reframePlan`'s `sightings` near the playhead) to draw boxes that call `onFaceClick` with the person's id:

```tsx
import { personColor, ReframeBox } from "@cutiva/react";

<div style={{ position: "relative", aspectRatio: `${asset.width} / ${asset.height}` }}>
  <SourceFrame /> {/* for example a canvas drawn from engine.sourceFrame(assetId, sourceUs) */}
  <ReframeBox
    editor={editor}
    clipId={clipId}
    timeUs={timeUs}
    faces={facesNow.map((f) => ({ ...f, id: f.personId, label: nameOf(f.personId), color: personColor(track, f.personId) }))}
    onFaceClick={(id) => engine.editReframe(clipId, { type: "segment", segmentId, focus: [id], layout: "single" })}
    onWindow={(window) => engine.editReframe(clipId, { type: "segment", segmentId, window })}
  />
</div>
```

The container must have the source's exact aspect ratio, so the window lines up with the picture. `placedSegments(clip)` and `segmentCaption(track, segment)` give the lanes' timing and labels for custom UIs.

## Crop keys by hand

The framing is a `core/reframe` effect holding keys in **source time**, so splitting, trimming or changing speed keeps it. Set them with one command:

```ts
editor.dispatch({
  type: "clip.setReframe",
  clipId,
  keys: [
    { atUs: 0, x: 480, y: 540, h: 1080 },                      // centre at (480, 540), full height
    { atUs: 12_000_000, x: 1440, y: 540, h: 1080, cut: true }, // jump to the right at 12 s
    { atUs: 15_000_000, x: 1500, y: 540, h: 900 },             // glide right and zoom in by 15 s
  ],
});
```

The exact rules (rounding, clamping, gliding) are in the [project format](/docs/project-format#rules-every-sdk-follows).

## Expo and React Native (Android, beta)

`@cutiva/expo` reframes a video on the phone in one call: it analyses the video natively (MediaPipe, the same model, tiles and mouth measure as the web), plans with `planReframe` from `@cutiva/core` in JavaScript, and exports the MP4 with the Cutiva Android engine. It needs a development build (`npx expo run:android`); Expo Go can't load it.

```ts
import { reframeVideo } from "@cutiva/expo";

const result = await reframeVideo(videoUri, { onProgress: (ratio, stage) => {} });
// result.uri: the vertical MP4. result.track: who speaks when, and the shot of each segment.

// Correct a shot: re-plans from the kept analysis, then exports again.
const fixed = await reframeVideo(videoUri, {
  analysis: result.analysis,
  track: result.track,
  edits: [{ type: "segment", segmentId: result.track.segments[0].id, layout: "wide" }],
});
```

**Status: Android only, tested on the Android 15 emulator.** On the real 48 s podcast clip the phone's analysis matches the web's (same speaker turns, edges within 0.2 s, one stretch with an off-camera voice differs); it took about 3 minutes on the emulator, and real phones need measuring. MediaPipe's Android library sends anonymous usage statistics (task name, latency, device model) to Google; no frames, faces or results leave the phone. iOS is planned. See [`packages/expo`](https://github.com/cutiva-dev/cutiva/tree/main/packages/expo) and the [example app](https://github.com/cutiva-dev/cutiva/tree/main/apps/expo-example).

## Other platforms

The planning step (`planReframe`, and the older `autoReframe`) is in the core and in the Dart core (`cutiva_core`), so it gives the same keys everywhere. A platform only needs to supply observations: for each sampled frame, its faces (box and mouth openness) and optionally speech loudness, plus camera cuts from `detectCuts`. On Android the engine's `reframe` module measures them; on iOS that can be Apple Vision or MediaPipe. Flutter is [planned](https://github.com/cutiva-dev/cutiva/blob/main/ROADMAP.md).

## How it decides

For each shot (cuts split the clip):

1. **Track faces.** Faces in consecutive frames are the same person when their centres are closer than 0.75 of the larger face's width, matching the closest pairs first. People seen in fewer than 20% of the shot's frames (and fewer than 2) are dropped as noise.
2. **Find the speaker.** Mouth movement is the change in mouth openness from one frame to the next, averaged over 400 ms on each side. The person with the most movement, at least 0.02, is speaking. Frames quieter than 0.1 of the clip's speech level count as silence: nobody new takes the frame.
3. **Hold.** Nobody speaking keeps the last speaker; before anyone speaks, the first speaker; if nobody speaks at all, the most visible person. A speaker keeps the frame at least 1.5 s (`minHoldUs`): shorter turns fold into the previous one.
4. **Write keys.** Each speaker change is a cut. The window is as tall as the source (or `1 / zoom` of it), with the face centre 15% of the window height above the window's centre. While one person speaks, positions are averaged over 500 ms and the window follows only after they move more than 5% of its size.

Shots with no faces are centred.

## The reframe planner

`planReframe(input)` is what `engine.reframe` runs, in the core and the Dart core. Next to `autoReframe` it also decides *how* each stretch is framed (one person, a split for two, or wide) and returns a Reframe Track (who speaks when, the people, the user's locked choices) next to the keys, plus `sightings`: each kept face with the person it belongs to (not stored in the project). Re-run it after every edit with the clip's current track: names, flags, merges and locked segments carry over. `editReframeTrack(track, edit)` applies the editor's changes (a segment's layout or focus, reset to automatic, a person's name, priority or never-focus, merging two people, camera style).

Pass `minShotUs` to keep every shot at least that long, for example `2_000_000` for a brand that wants no shot under 2 s. It raises the camera style's minimum and is not stored in the track. Input per analysed frame: faces (box, mouth openness or `null` when the mouth can't be seen, optional confidence, optional `speaking`), the speech level (omit on every frame when there is no audio) and an optional stereo pan. Times are integer µs of source time, sizes source pixels.

1. **Passthrough.** If the active area already has the output's shape (within 2%), one key shows all of it and there are no segments.
2. **Faces.** Faces under 0.6 confidence, shorter than 4% of the frame or centred outside the active area are dropped; at most the four largest per frame count.
3. **Tracking.** Within a shot, a face continues a track when their boxes overlap by IoU 0.3 or more (best pairs first) and the track was seen in the last second; otherwise it starts a new one. Then broken tracks are re-linked: in order of first sighting, a track joins the nearest earlier track that ended before it started, when its first face is within 1.5 face widths of that track's last face (a small face that leans, or someone whose face wasn't found for a while, in the same seat). Gaps up to 1 s are interpolated; through a longer gap the last position is held. Tracks seen in fewer than 20% of the shot's frames (and fewer than 2) are noise; at most four per shot. Each track is a person (`p1`, `p2`, … by first appearance), unless the user merged them.
4. **Voice.** Speech level 0.1 and above is voice. Gaps under 300 ms are filled, bursts under 250 ms dropped. Without audio every frame counts as voiced.
5. **Lips.** The standard deviation of mouth openness within 500 ms on each side (five samples at 5 fps), divided by 0.05 and capped at 1. Fewer than two visible mouths: no lip signal (`null`, not 0). If the person's faces carry `speaking` (0 to 1, from an active-speaker model such as Light-ASD that watches the face and listens to the audio together), the mean `speaking` within the same 500 ms replaces lip activity in the score, the candidate test and the overlap test; a person without it falls back to their lips.
6. **Score.** Per person and voiced frame: `0.6 lips + 0.25 pan + 0.05 continuity`, divided by the weights of the signals present. Pan scores `1 - |pan - p|` (at least 0), where `p` is the face's position from -1 (left) to 1 (right); continuity is 1 for the current speaker.
7. **Who is framed.** A candidate is a visible, not never-focus face with lips of 0.3 or more, or with no lip signal; with `speaking`, a mean of 0.5 or more. No faces: no-face. Voice with no candidate: voice-only (or never-focus, if the only one talking is never-focus). A new speaker takes over when the current one is out of sight, or after holding a claim for the style's hold time: they claim the frame by beating the current speaker by 0.15, and keep the claim while they score higher than the current speaker, including frames where nobody's lips move. The change is back-dated to when the claim started. Two candidates over 0.5 with moving lips are an overlap. Ties go to the priority person, then to the lower id.
8. **Durations.** Overlaps shorter than 1.5 s go to the current speaker; voice-only stretches of 1 s or less, and silences, keep the framing before them (at a shot's start, the shot's first speaker, else its most visible person).
9. **Segments.** Runs of one decision, with the previous track's locked segments put back unchanged. Segments shorter than the style's minimum (or than the input's `minShotUs`, if longer) fold into the neighbour before them (or after, at the start). Edges closer than 400 ms to a camera cut move onto it, so a segment can end up to 400 ms shorter than the minimum.
10. **Layouts.** One speaker: single. An overlap: single if both faces fit in one window, else a split. Voice-only, no-face and never-focus: wide. A split that would need more than `maxUpscalePct` (default 200%) of upscaling frames, as a single, whoever held the frame most of that stretch (reason `overlap`); a single that would need more goes wide with reason `low-quality`.
11. **Camera.** A single window is as tall as the active area (divided by the zoom), with the top of the face 12% below the window's top. Each segment starts with a cut. The window starts moving when the face leaves the dead zone and follows until it is within 1 px, through a One Euro filter (beta 1, derivative cutoff 1 Hz) capped at a top speed; keys are rounded half up. Split regions hold still, sized so the face is 35% of the region's height. Wide keys and split keys also carry a centred single window for renderers that don't draw layouts yet.

| Camera style | Calm (0) | Balanced (50) | Dynamic (100) |
| --- | --- | --- | --- |
| Hold before switching | 1.6 s | 1.0 s | 0.4 s |
| Shortest segment | 1.5 s | 1.0 s | 0.6 s |
| Dead zone (share of the window) | 6% | 4% | 2% |
| One Euro minimum cutoff | 0.3 Hz | 0.8 Hz | 1.5 Hz |
| Top speed (windows per second) | 0.15 | 0.25 | 0.4 |

Values in between are linear (times rounded half up to whole µs). The constants are starting points, to be tuned against real footage. Conformance fixtures `conformance/fixtures/auto-reframe/plan-*.json` pin the output for TypeScript and Dart.

## Feedback from the playground

After an auto-reframe, the [playground](/play) lists each framing change. Mark each one right or wrong, fix the wrong ones by dragging the window, rate the result and press **Report on GitHub**. The report downloads as a JSON file and a GitHub issue opens with a summary filled in; drag the file into the issue and submit it (you need a GitHub account, and the issue is public). The report holds numbers only: face boxes, mouth movement, speech levels, and the clip's Reframe Track and keys with your fixes (locked segments, flags, style). Names you typed are replaced by ids. No video, images or file names.

Reports are how auto-reframe improves: each one attached to an issue replays through `planReframe` offline, so a change to the rules can be measured against real corrections before it ships, and bad cases become regression tests.

## Known limits

- It reads mouths, so profiles, covered mouths, overlapping talk and off-screen voices fool it.
- With tiles, analysis runs at about the clip's real time (a 3-minute clip takes about 3 minutes).
- A person in two shots counts as two people (merge them in People).
- The source monitor's window shows the single fallback window on split and wide segments, not the two regions or the whole picture.
- On mobile: Android only (`@cutiva/expo`, tested on the emulator); iOS is planned.
- Changing the project's format reshapes the windows but doesn't re-plan the layouts; call `engine.reframe(clipId)` again, which re-plans from the cached analysis.
- Cuts are found at the analysis rate (every 200 ms), so a framing change can land up to one sample late.
