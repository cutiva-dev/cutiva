title: Auto-reframe
description: Turn landscape footage into vertical video that follows whoever is talking.
---

**Status: beta, needs testing.** An E2E test checks, in Chrome and Firefox, that dragging the window changes both preview and export. A manual test (it needs the network) checks that MediaPipe loads and analyses a clip. How well it picks the speaker in real conversations has not been measured yet.

Auto-reframe crops a landscape clip for a vertical (or square) project. It watches the clip, finds the people, works out who is talking from mouth movement and speech, and writes **crop keys**: a cut to each new speaker, and a gentle follow while they move. You then fix the keys it gets wrong by dragging the window.

## Web

Set the project's format, then reframe a clip. Face detection is pluggable; `@cutiva/web/mediapipe` provides a detector on MediaPipe Face Landmarker (Apache-2.0). Install it yourself, it is an optional peer dependency:

```bash
npm install @mediapipe/tasks-vision@1.1.1
```

```ts
import { createEditor } from "@cutiva/core";
import { createWebEngine } from "@cutiva/web";
import { createMediaPipeFaceDetector } from "@cutiva/web/mediapipe";

const editor = createEditor();
const engine = createWebEngine(editor);
const { clipId } = await engine.importFile(file);

editor.dispatch({ type: "project.setSize", width: 1080, height: 1920 }); // 9:16
const detector = await createMediaPipeFaceDetector();
const result = await engine.autoReframe(clipId!, {
  detector,
  onProgress: (ratio) => console.log(`${Math.round(ratio * 100)}%`),
});

result.people; // [{ id: "s0p0", speakingUs: 17_000_000, face: { x, y, w, h, atUs } }, ...]
editor.undo(); // the whole reframe is one undo step
```

Analysis decodes 5 frames per second, which is the slow part. To try another zoom without decoding again, pass the earlier analysis back: `engine.autoReframe(clipId, { detector, analysis: result.analysis, zoom: 1.5 })`.

The MediaPipe detector downloads its WASM files and model (about 4 MB) from jsDelivr and Google the first time. Pass `wasmBaseUrl` and `modelAssetPath` to host them yourself. Video frames never leave the device.

## React

`<Timeline>` marks each framing change on the clip; click a mark to seek there. `<ReframeBox>` draws the crop window over the uncropped source, and dragging it moves the framing at the playhead:

```tsx
import { ReframeBox } from "@cutiva/react";

<div style={{ position: "relative", aspectRatio: `${asset.width} / ${asset.height}` }}>
  <SourceFrame /> {/* for example a canvas drawn from engine.sourceFrame(assetId, sourceUs) */}
  <ReframeBox editor={editor} clipId={clipId} timeUs={timeUs} />
</div>
```

The container must have the source's exact aspect ratio, so the window lines up with the picture.

## Crop keys by hand

The framing is a `core/reframe` effect holding keys in **source time**, so splitting, trimming or changing speed keeps it. Set them with one command:

```ts
editor.dispatch({
  type: "clip.setReframe",
  clipId,
  keys: [
    { atUs: 0, x: 480, y: 540, h: 1080 },                      // centre at (480, 540), full height
    { atUs: 12_000_000, x: 1440, y: 540, h: 1080, cut: true }, // jump to the right at 12 s
    { atUs: 15_000_000, x: 1500, y: 540, h: 900 },             // glide right and zoom in by 15 s
  ],
});
```

The exact rules (rounding, clamping, gliding) are in the [project format](/docs/project-format#rules-every-sdk-follows).

## Other platforms

The planning step, `autoReframe(input)`, is in the core and in the Dart core (`cutiva_core`), so it gives the same keys everywhere. A platform only needs to supply observations: for each sampled frame, its faces (box and mouth openness) and optionally speech loudness, plus camera cuts from `detectCuts`. On iOS that can be Apple Vision; on Android, MediaPipe Tasks. Flutter and React Native engines are [planned](https://github.com/cutiva-dev/cutiva/blob/main/ROADMAP.md).

## How it decides

For each shot (cuts split the clip):

1. **Track faces.** Faces in consecutive frames are the same person when their centres are closer than 0.75 of the larger face's width, matching the closest pairs first. People seen in fewer than 20% of the shot's frames (and fewer than 2) are dropped as noise.
2. **Find the speaker.** Mouth movement is the change in mouth openness from one frame to the next, averaged over 400 ms on each side. The person with the most movement, at least 0.02, is speaking. Frames quieter than 0.1 of the clip's speech level count as silence: nobody new takes the frame.
3. **Hold.** Nobody speaking keeps the last speaker; before anyone speaks, the first speaker; if nobody speaks at all, the most visible person. A speaker keeps the frame at least 1.5 s (`minHoldUs`): shorter turns fold into the previous one.
4. **Write keys.** Each speaker change is a cut. The window is as tall as the source (or `1 / zoom` of it), with the face centre 15% of the window height above the window's centre. While one person speaks, positions are averaged over 500 ms and the window follows only after they move more than 5% of its size.

Shots with no faces are centred.

## The reframe planner

`planReframe(input)` is the next version of auto-reframe, in the core and the Dart core. It also decides *how* each stretch is framed (one person, a split for two, or wide) and returns a Reframe Track (who speaks when, the people, the user's locked choices) next to the keys. The playground still uses `autoReframe`; it switches to the planner when the editor gets the People panel and per-segment layouts. Re-run it after every edit with the clip's current track: names, flags, merges and locked segments carry over. `editReframeTrack(track, edit)` applies the editor's changes (a segment's layout or focus, reset to automatic, a person's name, priority or never-focus, merging two people, camera style).

Input per analysed frame: faces (box, mouth openness or `null` when the mouth can't be seen, optional confidence), the speech level (omit on every frame when there is no audio) and an optional stereo pan. Times are integer µs of source time, sizes source pixels.

1. **Passthrough.** If the active area already has the output's shape (within 2%), one key shows all of it and there are no segments.
2. **Faces.** Faces under 0.6 confidence, shorter than 4% of the frame or centred outside the active area are dropped; at most the four largest per frame count.
3. **Tracking.** Within a shot, a face continues a track when their boxes overlap by IoU 0.3 or more (best pairs first) and the track was seen in the last second; otherwise it starts a new one. Tracks seen in fewer than 20% of the shot's frames (and fewer than 2) are noise; at most four per shot. Each track is a person (`p1`, `p2`, … by first appearance), unless the user merged them.
4. **Voice.** Speech level 0.1 and above is voice. Gaps under 300 ms are filled, bursts under 250 ms dropped. Without audio every frame counts as voiced.
5. **Lips.** The standard deviation of mouth openness within 250 ms on each side, divided by 0.05 and capped at 1. Fewer than two visible mouths: no lip signal (`null`, not 0).
6. **Score.** Per person and voiced frame: `0.6 lips + 0.25 pan + 0.15 continuity`, divided by the weights of the signals present. Pan scores `1 - |pan - p|` (at least 0), where `p` is the face's position from -1 (left) to 1 (right); continuity is 1 for the current speaker.
7. **Who is framed.** A candidate is a visible, not never-focus face with lips of 0.3 or more, or with no lip signal. No faces: no-face. Voice with no candidate: voice-only (or never-focus, if the only one talking is never-focus). A new speaker takes over when the current one is out of sight, or after beating them by 0.15 for the style's hold time; the change is back-dated to when they started. Two candidates over 0.5 with moving lips are an overlap. Ties go to the priority person, then to the lower id.
8. **Durations.** Overlaps shorter than 1.5 s go to the current speaker; voice-only stretches of 1 s or less, and silences, keep the framing before them (at a shot's start, the shot's first speaker, else its most visible person).
9. **Segments.** Runs of one decision, with the previous track's locked segments put back unchanged. Segments shorter than the style's minimum fold into the neighbour before them (or after, at the start). Edges closer than 400 ms to a camera cut move onto it.
10. **Layouts.** One speaker: single. An overlap: single if both faces fit in one window, else a split. Voice-only, no-face and never-focus: wide. A single or split that would need more than `maxUpscalePct` (default 200%) of upscaling goes wide with reason `low-quality`.
11. **Camera.** A single window is as tall as the active area (divided by the zoom), with the top of the face 12% below the window's top. Each segment starts with a cut. The window starts moving when the face leaves the dead zone and follows until it is within 1 px, through a One Euro filter (beta 1, derivative cutoff 1 Hz) capped at a top speed; keys are rounded half up. Split regions hold still, sized so the face is 35% of the region's height. Wide keys and split keys also carry a centred single window for renderers that don't draw layouts yet.

| Camera style | Calm (0) | Balanced (50) | Dynamic (100) |
| --- | --- | --- | --- |
| Hold before switching | 1.6 s | 1.0 s | 0.4 s |
| Shortest segment | 1.5 s | 1.0 s | 0.6 s |
| Dead zone (share of the window) | 6% | 4% | 2% |
| One Euro minimum cutoff | 0.3 Hz | 0.8 Hz | 1.5 Hz |
| Top speed (windows per second) | 0.15 | 0.25 | 0.4 |

Values in between are linear (times rounded half up to whole µs). The constants are starting points, to be tuned against real footage. Conformance fixtures `conformance/fixtures/auto-reframe/plan-*.json` pin the output for TypeScript and Dart.

## Feedback from the playground

After an auto-reframe, the [playground](/play) lists each framing change. Mark each one right or wrong, fix the wrong ones by dragging the window, rate the result and press **Report on GitHub**. The report downloads as a JSON file and a GitHub issue opens with a summary filled in; drag the file into the issue and submit it (you need a GitHub account, and the issue is public). The report holds numbers only: face boxes, mouth movement, speech levels, the keys auto-reframe made and the keys after your fixes. No video, images or file names.

Reports are how auto-reframe improves: each one attached to an issue replays through `autoReframe` offline, so a change to the rules can be measured against real corrections before it ships, and bad cases become regression tests.

## Known limits

- It reads mouths, so profiles, covered mouths, overlapping talk and off-screen voices fool it.
- A person in two shots counts as two people.
- Cuts are found at the analysis rate (every 200 ms), so a framing change can land up to one sample late.
