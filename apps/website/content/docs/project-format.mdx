title: Project format (CPF)

A Cutiva project is a JSON document called **CPF** (Cutiva Project Format). A project saved on one platform opens on any other.

- **Assets** are the media files, identified by id and a fingerprint (size and a hash of the first 64 KiB) so they can be relinked on another device.
- **Tracks** are `video` or `audio`. Video tracks are drawn in array order; later tracks draw on top.
- **Clips** place a range of an asset (`sourceInUs` to `sourceOutUs`) at a position on the timeline (`startUs`), with `speed`, `volume` and effects.

All times are **integer microseconds**. `12_000_000` is twelve seconds.

```json
{
  "version": "0.1.0",
  "id": "prj_8f2a",
  "settings": { "width": 1080, "height": 1920, "fps": { "num": 30, "den": 1 }, "sampleRate": 48000 },
  "assets": [{ "id": "ast_v1", "kind": "video", "name": "intro.mp4", "uri": "file://intro.mp4", "durationUs": 42000000 }],
  "tracks": [{ "id": "trk_v1", "kind": "video", "muted": false, "clips": [
    { "id": "clip_1", "assetId": "ast_v1", "startUs": 0, "sourceInUs": 2000000, "sourceOutUs": 12000000, "speed": 1, "volume": 1, "effects": [] }
  ]}]
}
```

`parseProject()` validates a document and reports the exact path of any error.

## Rules every SDK follows

These rules define what a project means. The conformance fixtures in `conformance/fixtures` are written from them.

**Rounding.** Where a rule says *round*, round to the nearest integer, with halves going up (`round(2.5) = 3`). All inputs are non-negative, so this matches `Math.round` in JavaScript and `round()` in Dart, Swift and Kotlin.

**Clips.**
- A clip lasts `round((sourceOutUs - sourceInUs) / speed)` on the timeline.
- It occupies the half-open range `[startUs, startUs + duration)`: at its end time it is no longer visible.
- At timeline time `t` inside that range, it shows source time `sourceInUs + round((t - startUs) * speed)`.
- Clips on one track never overlap and are stored in order of `startUs`. Gaps between them are allowed.
- A clip's asset has the same kind as its track: video assets on video tracks, audio assets on audio tracks.
- `speed` is between 0.1 and 16, and `volume` is between 0 and 4.

**Project duration** is the latest clip end on any track, or 0 when there are no clips.

**Video.** At time `t`, each video track shows the clip that contains `t`, if any. Layers are listed in track order, bottom first; later tracks draw on top. A muted video track is still visible.

**Render plan.** `renderPlan(project)` lists the same thing flat, for native engines: every video clip as a segment with its layer (its position among the video tracks, 0 at the bottom), its timeline range `[startUs, endUs)`, its source range and speed; the audio segments above with their asset URIs; the duration and settings. Clips whose asset is missing are left out.

**Audio.** Every clip on a track that is not muted plays its sound, except clips of a video asset with `hasAudio: false` and clips with `volume` 0. Each one is an audio segment with the clip's start, source range, speed and volume, listed in track order and then clip order. A `core/fade` effect adds `inUs` and `outUs` fades, in timeline time; without one, both are 0.

**Reframe.** A video clip may carry a `core/reframe` effect whose `params.keys` is a list of crop keys `{ atUs, x, y, h, cut? }`, sorted by strictly increasing `atUs`. All values are integers; `x`, `y` and `atUs` are at least 0 and `h` at least 1. `atUs` is a **source** time of the asset; `(x, y)` is the centre of the crop window and `h` its height, in source pixels. Its width follows the project's aspect ratio (`width:height`). Reframing needs the asset's `width` and `height`.

For a source of `W x H` pixels and an output of `OW x OH`, a key becomes a rectangle, where `floor` rounds down and *round* rounds half up:

- `h' = min(max(h, 1), max(1, min(H, floor(W * OH / OW))))`, the tallest window that fits.
- `w' = min(max(round(h' * OW / OH), 1), W)`.
- `x' = min(max(floor((2x - w' + 1) / 2), 0), W - w')` and `y' = min(max(floor((2y - h' + 1) / 2), 0), H - h')`: centred on the key, pushed back inside the frame.

At source time `s`, the window is the rectangle of the last key at or before `s` (of the first key, before it starts). If the next key has `cut: true`, that rectangle holds until the next key's time and then jumps. Otherwise it glides towards the next key: with `dt` the time between the two keys, `u = s - t0` and `v = t1 - s`, each of the left, top, right and bottom edges is `floor((2 * (a * v + b * u) + dt) / (2 * dt))` for edge values `a` and `b`, and the width and height are right minus left and bottom minus top. Engines scale the window to fill the output frame. A clip without a reframe is drawn whole and letterboxed. In the render plan, a reframed segment has `crop`: the rectangles of the keys that matter for its source range (the last key at or before `sourceInUs` through the first key at or after `sourceOutUs`), with their `atUs` and `cut`.

**Auto-reframe** (`autoReframe`) is also a shared rule, so every SDK frames the same observations the same way. Its steps and constants are in the [auto-reframe guide](/docs/auto-reframe#how-it-decides).
