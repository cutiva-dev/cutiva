**Status: beta, iOS and Android.** Tested on the Android 15 emulator and the iOS simulator (iPhone 16 Pro); real phones need testing.

`@cutiva/expo` turns a landscape video into a vertical one that follows whoever is talking, entirely on the phone: no server, and frames never leave the device. It is a native Expo module ([ADR 0007](https://github.com/cutiva-dev/cutiva/blob/main/docs/adr/0007-mobile-reframe-first.md)).

## Install

```bash
npx expo install @cutiva/expo
npx expo run:ios       # or: npx expo run:android
```

It needs a **development build** (`npx expo run:ios`, `npx expo run:android` or EAS Build): Expo Go can't load native modules. Requirements: Expo SDK 58 or later, iOS 16.4 or later, Android 7 (API 24) or later. On iOS the module adds MediaPipe Tasks Vision 1.0.0 through CocoaPods.

Pass a `file://` URI. `expo-image-picker` gives one; Photos `ph://` URIs are rejected with `ASSET_NOT_FOUND`.

## Reframe a video

```tsx
import { reframeVideo } from "@cutiva/expo";
import * as ImagePicker from "expo-image-picker";

const picked = await ImagePicker.launchImageLibraryAsync({ mediaTypes: ["videos"] });
const result = await reframeVideo(picked.assets![0]!.uri, {
  onProgress: (ratio, stage) => console.log(stage, Math.round(ratio * 100)),
});

result.uri;      // file:// URI of the vertical MP4: play it with expo-video, or upload it
result.track;    // who speaks when, and the shot of each segment
result.analysis; // keep it for corrections
```

`stage` is `model` (the face model downloads once, 3.7 MB), `video` (finding faces), `audio` (speech) and `export`. Pass an `AbortSignal` as `signal` to cancel.

Options: `width` and `height` of the output (default 1080 x 1920; 1080 x 1080 for square), `fromUs` and `toUs` to reframe part of the video, `outputUri` for where to write the MP4.

## Correct a shot

Each segment of `result.track.segments` has an `id`, a time range (`startUs`, `endUs`, in microseconds), the people talking (`speakers`) and its shot (`resolved`: `single`, `split` or `wide`). People are in `result.track.people` (`p1`, `p2`, … with labels like "Speaker A").

To fix one, pass the earlier analysis and track with an edit. It re-plans in a moment and only the export takes time:

```ts
const fixed = await reframeVideo(uri, {
  analysis: result.analysis,
  track: result.track,
  edits: [{ type: "segment", segmentId: result.track.segments[2]!.id, layout: "single", focus: ["p2"] }],
});
```

| Edit | Does |
| --- | --- |
| `{ type: "segment", segmentId, layout: "single", focus: [personId] }` | Frame that person |
| `{ type: "segment", segmentId, layout: "split" }` | Two people, one in each half |
| `{ type: "segment", segmentId, layout: "wide" }` | The whole picture over a blurred copy |
| `{ type: "reset", segmentId }` | Give the segment back to the planner |
| `{ type: "person", personId, label, neverFocus, priority }` | Name a person, never frame them alone, or prefer them |
| `{ type: "settings", style }` | Camera style: 0 calm, 50 balanced, 100 dynamic |

Corrected segments are locked: re-planning never changes them.

## Step by step

`reframeVideo` is three steps you can also call yourself:

```ts
import { analyzeVideo, planVideo, reframedProject } from "@cutiva/expo";

const analysis = await analyzeVideo(uri);   // native: slow, numbers only
const plan = planVideo(analysis);           // JavaScript (@cutiva/core): fast
const { project } = reframedProject(uri, analysis, plan); // a Cutiva project (CPF) you can save
```

## Privacy and permissions

- Frames and audio stay on the phone; the analysis is numbers only (face boxes, mouth movement, loudness).
- The face model (MediaPipe Face Landmarker, Apache-2.0) downloads once and is checked against a pinned SHA-256; on Android the module adds the `INTERNET` permission for it.
- **MediaPipe's Android library sends anonymous usage statistics** to Google (task name, latency, device model). No images or results. Mention it in your privacy policy if it applies to you.
- MediaPipe's iOS library (1.0.0): a scan of its binaries found no usage-statistics code, but its network traffic hasn't been measured. Google's [MediaPipe privacy notice](https://goo.gle/mediapipe-privacy) applies.

## Speed and limits

- Analysis is the slow part. A 48-second 1080p clip took about 3 minutes on the Android emulator and about 2 minutes on the iOS simulator; phones should be faster, but this hasn't been measured yet. Keep `result.analysis` so corrections don't analyse again.
- Export on the iOS simulator is slow (about 7 minutes for that clip, drawn on the CPU); a real iPhone uses its GPU and hardware encoder and needs measuring.
- Sped-up clips: iOS changes the pitch, like the web; Android keeps it.
- Speech is measured by loudness, so music or noise can look like speech.
