Cutiva is not on npm yet. Until v0.1, run it from the repository:

```bash
git clone https://github.com/cutiva-dev/cutiva
cd cutiva
npm install
npm run build
npm run dev   # playground at http://localhost:5173
```

## Your first edit

```ts
import { createEditor } from "@cutiva/core";
import { createWebEngine } from "@cutiva/web";

const editor = createEditor({ settings: { width: 1920, height: 1080 } });
const engine = createWebEngine(editor);

const { clipId } = await engine.importFile(file);
editor.dispatch({ type: "clip.split", clipId: clipId!, atUs: 12_000_000 });

const job = engine.export({ resolution: "1080p" });
const mp4 = await job.done;
```

Export needs a browser that can encode H.264 with WebCodecs. Call `engine.capabilities()` first to check. Its `audioCodec` is `"aac"` in Chrome, Edge and Safari and `"opus"` where AAC can't be encoded (Firefox, Chrome on Linux); QuickTime and some phones can't play Opus in MP4.

## In React

`@cutiva/react` wraps the same editor and engine. `<Timeline>` shows a strip of thumbnails on video clips when you pass it `engine.thumbnail`:

```tsx
import { useState } from "react";
import { Timeline, useCutiva, usePreview } from "@cutiva/react";
import "@cutiva/react/styles.css";

function Editor() {
  const { editor, engine } = useCutiva({ settings: { width: 1920, height: 1080 } });
  const [canvas, setCanvas] = useState<HTMLCanvasElement | null>(null);
  const { preview, timeUs } = usePreview(engine, canvas);
  return (
    <>
      <canvas ref={setCanvas} />
      <Timeline editor={editor} timeUs={timeUs} onSeek={(t) => preview?.seek(t)} thumbnail={engine.thumbnail} />
    </>
  );
}
```

Thumbnails show the keyframe at or before each slot, so they cost one decode per keyframe.
